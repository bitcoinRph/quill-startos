# Draft formats

Fill from the notes only. Use `[to confirm]` for any gap. Show the draft to the user before any send.

## Follow-up email

```text
Subject: <Meeting title> - recap and next steps

Hi <names>,

Thanks for the time today. Here is what we agreed.

What we decided
- <Decision>

Next steps
- <Task> - <owner> - <due date or "date to confirm">

Open points
- <Question we still need to answer>

<Closing line asking for corrections.>

<Sender name>
```

Rules: no more than 150 words for the body. Do not add anything not in the notes. Do not include internal comments, private remarks or raw timestamps.

## Task list

```text
- [ ] <Verb> <object> - owner: <name> - due: <date or no date> - from <meeting title> [h:mm:ss]
```

Group by owner if there are more than five tasks. Create the tasks in a tool only after the user approves the list.

## CRM update

```text
Account / contact: <name>
Date: <meeting date>
Summary: <two sentences>
Stakeholders: <name - role, as stated>
Needs / pain: <bullets>
Objections / risks: <bullets>
Next step: <action> - <owner> - <date or "to confirm">
Suggested stage: <stage> (suggestion, not a fact)
```

Write what was said. Mark opinions as the speaker's. Do not set deal values, probabilities or stages as facts.

## Short Slack or chat recap

```text
Recap of <meeting>: <one-line outcome>.
Decisions: <a>, <b>.
Actions: <owner> - <task> (<date>).
```

Post it only after the user approves the text and the channel.
